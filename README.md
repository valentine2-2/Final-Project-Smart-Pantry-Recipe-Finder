## 📌 ภาพรวมโปรเจกต์ (Project Overview)
**Smart Pantry &amp; Recipe Finder** เป็นโปรแกรมแบบ Command-Line Interface (CLI) ที่ถูกออกแบบมาเพื่อช่วยจัดการวัตถุดิบในคลังอาหารของผู้ใช้ และช่วยค้นหาเมนูอาหารที่เหมาะสม เพื่อแก้ปัญหาการจัดการวัตถุดิบในชีวิตจริง [5, 6] 

ใน **Sprint 1** โปรเจกต์โฟกัสที่การสร้างโครงสร้างพื้นฐานของระบบ (Foundation) ได้แก่:
- เมนูต้อนรับและคำสั่งหลักของโปรแกรม (Main Program Loop) [7]
- โครงสร้างจัดเก็บข้อมูลวัตถุดิบหลัก (Pantry Catalog) [8]
- ระบบรับคำสั่งแบบไม่สนใจตัวพิมพ์เล็ก-ใหญ่ (Case-Insensitive Input) [8]
- คำสั่งดูวัตถุดิบ (`view`) และการออกจากโปรแกรมอย่างปลอดภัย (`quit`) [6, 8]

## 🔄 กระบวนการทำงานแบบ Agile &amp; DevOps Workflow

ทีมของเรายึดหลักการ **"บั๊กคือปัญหาของทั้งทีม" (The bug is the team's problem)** โดยไม่โยนความผิดให้คนใดคนหนึ่ง แต่ใช้บั๊กเป็นโอกาสในการพัฒนากระบวนการทำงานร่วมกัน[1]

```
[ Planner (ไทน์) ] ──(ส่งมอบ Task)──&gt; [ Coders (ฟ่า &amp; ภีม) ]
       ▲                                      │
       │                                 (ส่งโค้ดตรวจ)
  (ปรับปรุงแผน)                                │
       │                                      ▼
 [ บันทึก Task เสร็จสิ้น ] &lt;──(ผ่าน QA)── [ Debugger (โดนัท) ]
                                              │
                                       (พบบั๊ก/ส่ง Bug Report)
                                              │
                                              └──────&gt; [ แก้ไขโค้ด ]

```

### 1\. จังหวะการสื่อสารในทีม (Communication Rhythm)

* **Monday Huddle (5 นาที)**: Planner นำเสนอแผนงานประจำสัปดาห์ Coders และ Debugger ซักถามเพื่อให้เข้าใจตรงกัน 100% ก่อนเริ่มเขียนโค้ด[4][5]
* **Mid-Week Handoff**: Coders ส่งมอบโค้ดให้ Debugger ผ่าน Pull Request พร้อมอธิบายส่วนที่พัฒนา[6][7]
* **Friday Review (15 นาที)**: Debugger รายงานผลการทดสอบ ร่วมกันแก้ไขข้อผิดพลาด และทบทวนบทเรียนประจำสัปดาห์[1]

### 2\. รูปแบบการรายงานบั๊ก (Structured Bug Report)

เมื่อ **โดนัท (Debugger)** พบข้อผิดพลาด จะทำการบันทึกผ่าน GitHub Issue โดยใช้รูปแบบมาตรฐาน 3 ส่วน[8][6]:

1. **What I did**: ระบุขั้นตอนการทดสอบ (เช่น *"พิมพ์ 'QUIT' ตัวพิมพ์ใหญ่"*[9][8])
2. **What I expected**: ระบุผลลัพธ์ที่ควรจะเป็นตาม Acceptance Criteria (เช่น *"โปรแกรมควรแสดงข้อความลาและปิดตัว"*[9][8])
3. **What actually happened**: ระบุสิ่งที่เกิดขึ้นจริง (เช่น *"โปรแกรมแจ้งเตือน Invalid command"*[8][6])

## 🤖 การใช้ AI เป็น Co-Pilot (AI Co-Pilot Philosophy)

ทีมของเราใช้เครื่องมือ AI ในฐานะ **"ผู้ช่วยเรียนรู้และติวเตอร์ส่วนตัว"**[10][11]:

* **ใช้ AI ในการ**: อธิบายแนวคิดทางเขียนโค้ด, ช่วยวิเคราะห์สาเหตุของข้อผิดพลาด (Diagnose Bugs), และเสนอแนะโครงสร้างไฟล์[11][12]
* **คนเป็น Pilot**: **ไทน์, ฟ่า, ภีม และโดนัท** ยังคงเป็นผู้กำหนดทิศทาง ตัดสินใจเชิงสถาปัตยกรรม นึกถึงผู้ใช้งาน และรับผิดชอบความถูกต้องของโค้ดทั้งหมด[13]
